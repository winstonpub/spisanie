# Развёртывание сайта на GitHub Pages

Ваш сайт — это статическое SPA-приложение на React + Vite, которое собирается в один HTML-файл. GitHub Pages — идеальный бесплатный хостинг для таких проектов.

## 🚀 Способ 1: Автоматическое развёртывание через GitHub Actions (рекомендуется)

### Шаг 1. Создание репозитория

1. Перейдите на [github.com/new](https://github.com/new)
2. Укажите название репозитория (например, `spisanie`)
3. Выберите **Public** (публичный) — GitHub Pages бесплатен для публичных репозиториев
4. Нажмите **Create repository**

### Шаг 2. Загрузка кода в репозиторий

В корне вашего проекта выполните команды:

```bash
# Инициализация Git (если ещё не сделано)
git init
git add .
git commit -m "Initial commit"

# Привязка к удалённому репозиторию (замените USERNAME и REPO)
git remote add origin https://github.com/USERNAME/REPO.git
git branch -M main
git push -u origin main
```

### Шаг 3. Настройка GitHub Pages

1. Откройте репозиторий на GitHub
2. Перейдите в **Settings** → **Pages** (в левом меню)
3. В разделе **Build and deployment** выберите:
   - **Source**: `GitHub Actions`
   - Ничего больше настраивать не нужно — workflow-файл уже в проекте (`.github/workflows/deploy.yml`)

### Шаг 4. Запуск развёртывания

GitHub Actions запустится автоматически при push в ветку `main` или `master`. Вы также можете запустить его вручную:

1. Перейдите в **Actions** → **Deploy to GitHub Pages**
2. Нажмите **Run workflow** → **Run workflow**

### Шаг 5. Получение URL сайта

После успешного развёртывания ваш сайт будет доступен по адресу:

```
https://USERNAME.github.io/REPO/
```

Например, если ваш username `ivan` и репозиторий `spisanie`:
```
https://ivan.github.io/spisanie/
```

## 🔧 Способ 2: Ручная загрузка в ветку `gh-pages`

Если вы не хотите использовать GitHub Actions:

### Шаг 1. Установка утилиты `gh-pages`

```bash
npm install --save-dev gh-pages
```

### Шаг 2. Добавление скрипта в `package.json`

Откройте `package.json` и добавьте скрипт `deploy`:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "deploy": "gh-pages -d dist"
  }
}
```

### Шаг 3. Настройка `vite.config.ts` (опционально)

Если репозиторий не называется `username.github.io`, добавьте `base` в `vite.config.ts`:

```typescript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  base: '/REPO/', // замените на название репозитория
})
```

### Шаг 4. Сборка и развёртывание

```bash
npm run build
npm run deploy
```

Эта команда создаст ветку `gh-pages` с содержимым папки `dist` и запушит её на GitHub.

### Шаг 5. Настройка GitHub Pages

1. Перейдите в **Settings** → **Pages**
2. В разделе **Source** выберите **Deploy from a branch**
3. Выберите ветку `gh-pages` и папку `/ (root)`
4. Нажмите **Save**

Через 1-2 минуты сайт будет доступен по адресу `https://USERNAME.github.io/REPO/`.

## 🌐 Настройка кастомного домена (опционально)

Если у вас есть собственный домен (например, `spisanie.ru`):

1. В корне проекта создайте файл `public/CNAME` с содержимым:
   ```
   spisanie.ru
   ```
2. У вашего DNS-провайдера добавьте записи:
   - **A**: `185.199.108.153`
   - **A**: `185.199.109.153`
   - **A**: `185.199.110.153`
   - **A**: `185.199.111.153`
   - **CNAME** (для `www`): `USERNAME.github.io`
3. В настройках GitHub Pages укажите кастомный домен
4. Включите **Enforce HTTPS**

## ⚠️ Важные замечания

### 1. Маршрутизация

Ваш сайт использует хэш-роутинг (`#/construction`, `#/admin`), поэтому **проблем с 404 не будет**. GitHub Pages корректно обрабатывает такие URL.

### 2. Кэширование

GitHub Pages кэширует файлы. После обновления сайта пользователи могут увидеть старую версию. Решения:
- Очистить кэш браузера (Ctrl+Shift+R)
- Добавить версионирование в `index.html` (например, `<script src="app.js?v=2">`)

### 3. Секреты и безопасность

**Никогда не храните API-ключи, токены или пароли в коде!** Ваш сайт публичный, и любой может посмотреть исходный код.

Для Apps Script URL:
- URL хранится в `localStorage` браузера пользователя (в разделе настроек)
- Это безопасно: каждый пользователь настраивает свой URL
- Apps Script выполняется от имени того, кто его развернул

### 4. Ограничения GitHub Pages

- **100 МБ** на файл
- **1 ГБ** на репозиторий
- **100 ГБ** трафика в месяц
- **10 ГБ** трафика на репозиторий в месяц

Для вашего сайта (один HTML ~500 КБ) этих лимитов хватит с запасом.

### 5. HTTPS

GitHub Pages автоматически включает HTTPS для всех сайтов. Пользователи будут перенаправлены с `http://` на `https://`.

## 🔍 Проверка работы

После развёртывания проверьте:

1. **Главная страница** открывается: `https://USERNAME.github.io/REPO/`
2. **Переключение отделов** работает через навигацию в шапке
3. **Страница настроек** доступна: `https://USERNAME.github.io/REPO/#/admin`
4. **Apps Script** записывает данные в Google Таблицу (если URL настроен)

Если что-то не работает:
- Откройте консоль браузера (F12) и проверьте ошибки
- Проверьте вкладку **Actions** в репозитории — возможно, сборка не удалась
- Убедитесь, что репозиторий публичный (GitHub Pages не работает для приватных репозиториев на бесплатном плане)

## 📝 Обновление сайта

При каждом push в ветку `main` GitHub Actions автоматически:
1. Собирает проект (`npm run build`)
2. Загружает артефакт
3. Развёртывает на GitHub Pages

Вы увидите статус в разделе **Actions**. Зелёная галочка = развёртывание успешно.

Чтобы обновить сайт:

```bash
git add .
git commit -m "Update: исправил баг / добавил функцию"
git push
```

Через 1-2 минуты изменения появятся на сайте.

## 🆘 Частые проблемы

### Проблема: «404 Not Found»
**Решение**: Убедитесь, что в настройках Pages выбрана правильная ветка и источник (GitHub Actions или `gh-pages`).

### Проблема: «Сайт загружается, но стили не работают»
**Решение**: Проверьте `base` в `vite.config.ts`. Он должен соответствовать названию репозитория.

### Проблема: «Apps Script не записывает данные»
**Решение**: Убедитесь, что URL Apps Script корректен и скрипт развёрнут с доступом «Все».

### Проблема: «Старая версия сайта после обновления»
**Решение**: Очистите кэш браузера (Ctrl+Shift+R) или добавьте версионирование.
