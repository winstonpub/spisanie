# Настройка Google Apps Script

Сайт использует одно веб-приложение Apps Script для списков списания и для пошагового добавления товаров. Актуальный код находится в `google-apps-script/Code.gs`.

## Обновление скрипта

**Для добавления новых товаров нужна версия 3. Старый скрипт не поддерживает эти команды.** Сайт не может опубликовать скрипт в вашем Google-аккаунте автоматически.

1. Откройте Google Таблицу и выберите **Расширения → Apps Script**.
2. Полностью замените содержимое `Code.gs` кодом из `google-apps-script/Code.gs` в проекте.
3. Сохраните проект.
4. Откройте **Развернуть → Управление развёртываниями → Изменить**.
5. Выберите **Версия → Новая версия → Развернуть**. URL существующего развёртывания останется прежним.
6. Если Google повторно попросит разрешения, подтвердите доступ к таблицам.
7. Обновите сайт и попробуйте добавить товар.

При первом развёртывании выберите тип **Веб-приложение**, **Выполнять как: Я**, **У кого есть доступ: Все**. Для Google Workspace эта возможность может быть ограничена администратором организации.

## URL скрипта

URL веб-приложения должен заканчиваться на `/exec`. Сайт получает его из ячейки A1 листа `gid=37870238` документа `1lPe5aSe2SG9ZXDTF7hKNlqAU9dS34IgJXwteSZVGsZ4`. Его также можно обновить в настройках сайта.

## Листы

| Страница | База товаров A:C | Список списания A:B |
|---|---|---|
| Строительные материалы | gid=0 | gid=1410594629 |
| Столярные изделия | gid=1557440748 | gid=317840889 |

Ссылка «Таблица товаров» в настройках определяет документ и лист, в который форма добавляет товар. Клиент передаёт **и идентификатор документа, и gid**, а не лист списания.

Новые товары разрешены только в целях из `PRODUCT_CATALOGS` в скрипте. Если подключаете другую базу, владелец скрипта должен явно добавить её документ и gid в этот список и развернуть новую версию. Записи в произвольные доступные владельцу таблицы не разрешены.

## Добавление товара

1. После ввода неизвестного артикула сайт предлагает «Добавить новый?». Окно появляется после паузы ввода или по Enter, когда база загружена. Загруженные ранее строки сами по себе окно не открывают.
2. Кнопка **«Добавить»** отправляет `product.begin`. Скрипт проверяет наличие артикула и записывает его в A новой строки после последней занятой строки A:C.
3. На следующем шаге введите штрихкод или воспользуйтесь камерой. **«Подтвердить»** отправляет `product.barcode` и записывает B **той же строки**.
4. Введите название товара. **«Подтвердить»** отправляет `product.name`, записывает C той же строки и завершает добавление.
5. После подтверждения сервера окно закрывается, наименование и штрихкод появляются в рабочей таблице и печатной форме.

Пустые ячейки B/C в старых строках не используются для нового товара: данные разных товаров не смешиваются. Значения записываются текстом, ведущие нули сохраняются. Наименование, начинающееся с `=`, не исполняется как формула.

## Отмена и повтор

- **«Закрыть»** до нажатия «Добавить» ничего не записывает в базу товаров.
- На следующих шагах **«Закрыть»** отправляет `product.cancel` и очищает только A:C собственного незавершённого товара. Другие строки и столбцы не удаляются и не сдвигаются.
- При сетевой ошибке можно повторить то же действие: идентификатор операции предотвращает дублирование.
- Если другой пользователь изменил черновик, автоматическая отмена запрещена. Сайт покажет причину, данные останутся на месте.
- Если сервер уже сохранил полный товар, отмена не удалит его.
- Если закрыть вкладку браузера или потерять связь до отмены, незавершённые поля могут остаться в Google Таблице. Проверьте их вручную. Кнопка «Закрыть без удаления черновика» явно оставляет такую запись.
- Завершённые операции хранятся в свойствах скрипта семь дней для защиты от повторов; незавершённые черновики автоматически не удаляются.

## Списки списания

Обычные команды `log` и `clear` продолжают работать. Они изменяют только A:B листов списания и по-прежнему **не могут очистить базу товаров или лист настроек**. Версия ответа теперь 3, сайт принимает версии 2 и выше для этих старых команд.

## Безопасность

Веб-приложение с доступом «Все» выполняется от имени владельца. Любой, кому известен URL, может вызвать разрешённые команды. Не считайте URL паролем. Для закрытого использования настройте аутентификацию и серверную проверку пользователей до публикации конфиденциальных данных.

Не добавляйте в `PRODUCT_CATALOGS` чужие или конфиденциальные таблицы. Если ограничить развёртывание только авторизованными Google-пользователями, текущие анонимные запросы со статического сайта могут перестать работать.

## Проверка и ошибки

- **«Обновите Apps Script»**: код сохранён, но новая версия ещё не развёрнута, либо A1 содержит URL другого развёртывания.
- **«База не разрешена в PRODUCT_CATALOGS»**: документ или gid из настроек сайта не входит в список разрешённых баз.
- **«Нет подтверждения от Google»**: проверьте сеть и доступ веб-приложения. Успешная отправка без читаемого ответа не считается сохранением.
- В Apps Script откройте **Выполнения**, чтобы увидеть ошибки прав, защищённых диапазонов или квот.
- Для локальной проверки серверной логики без записи в настоящие Google Таблицы: `node --test tests/catalog-script.test.cjs`.
